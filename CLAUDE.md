## Commands

- `docker compose run --rm demo` — create database `delta`, install the module, load demo data.
- `docker compose run --rm test` — run the module tests on database `delta_test`; exit code 0 = green.
- `docker compose up -d odoo` — UI at http://localhost:8069, database `delta`, admin / admin (auditor / auditor for the read-only role).
- `python docs/oracle.py --check` — the committed expected figures match the seeds.
- `docker compose down -v` — reset everything, including volumes.

A step is done when `docker compose run --rm test` exits 0 on a clean database and `python docs/oracle.py --check` exits 0.

## Hard rules

- The module never creates or changes `account.move` or `account.move.line`, except the demo loader.
- Every group amount goes through `_translate`; there is no other currency conversion in the code.
- Demo data lives only in `delta_consolidation/data/demo_dataset.json`. No amounts, dates or names in loader or test code.
- Never edit `delta_consolidation/tests/expected_figures.json` by hand. If the seeds or the rules change, run `python docs/oracle.py` and commit both files. A mismatch between the module and the expected figures is a reason to stop and investigate, never to change the expected figures.
- `docs/oracle.py` must not import Odoo or the module: it is the independent check.

## Odoo 18.0 pitfalls (verified against the 18.0 source)

- Do not set `country_id` on the demo companies: outside tests it triggers `l10n_*` installation and a different chart of accounts.
- Vendor bills: pass both `invoice_date` and `date` explicitly, otherwise `date` becomes the end of the invoice month.
- `account.payment` without an outstanding account creates no journal entry: demo payments and the loan are `move_type='entry'`.
- `account.account.code` is company-dependent: read it through `with_company(company)`.
- Reading journal items of all group companies: `with_context(allowed_company_ids=group.company_ids.ids)`.
- Exchange-difference lines carry the partner and `amount_currency = 0`: they are never mirrored.
- In manual entries set `partner_id` on every intercompany line explicitly.
- Create currency rates (`company_id=False`) before any document.
- `try_loading('generic_coa', company=c, install_demo=False)` needs a fully loaded registry and superuser rights: call the loader from `odoo shell` and from `post_install` tests, never from an install hook.
- New companies are linked only to the current user, and `odoo shell` runs as the superuser: add them to admin's `company_ids` explicitly. The user groups field is `groups_id` in 18.0 (`group_ids` in 19.0).
- `-i` alone reloads an already installed module and reruns its tests; `-u` is not needed.
- `odoo shell` rolls back at exit: `scripts/load_demo.py` must call `env.cr.commit()`.
- Post demo documents in date order, so the journal sequence checks never trip.
- `amount_local` on report lines has `aggregator=None`: the pivot must never sum UAH, PLN and USD.
- The read-only auditor cannot write report lines: the report wizard rebuilds them via `sudo()`.
- Prefer `@api.constrains` over `_sql_constraints` (removed in 19.0).
